Problem: Given n mochi with sizes sorted ascending. We need maximum number of stacks (kagamimochi) that can be made simultaneously, where each stack requires two mochi? Actually "kagamimochi is made by placing one mochi on top of another, where the top mochi's size must be at most half of the bottom mochi's size." So each kagamimochi is a pair (bottom and top). We want to create as many pairs as possible using each mochi at most once. This is typical pairing problem similar to "boats to save people" or "matching small with large where small <= large/2".

Goal: maximize number of pairs (i.e., stacks) such that for each pair (bottom larger, top smaller) top <= bottom/2 and each mochi used at most once.

Given sorted ascending sizes. We need max number of pairs.

Approach: Two-pointer greedy: split array into two halves: small half and large half. We'll try to match smallest unused small mochi with smallest large mochi that can serve as bottom (>= 2*top). But here condition is top <= bottom/2 => bottom >= 2*top. Equivalent to pair small with larger at least double.

Goal maximize pairs.

Standard approach: use two pointers i for small side (first half) and j for large side (midpoint). We'll iterate trying to match smallest possible small with moderate large. For n up to 5e5.

Procedure: Let i = 0 (first small index). Let j = n//2 (start of large side). Count pairs =0. While i < n//2 and j < n: if sizes[j] >= 2 * sizes[i], then pair them, increment count, i++, j++. Else j++ (look for larger bottom). At end result count is max pairs but cannot exceed n/2.

But need decide split point. Classic problem "maximum number of pairs where larger at least twice smaller" uses j starting at mid index (n/2) because you need at least as many large elements as small ones. Use i up to mid-1. However we need to ensure we consider all possible splits; starting j = ceil(n/2) ensures enough large candidates.
