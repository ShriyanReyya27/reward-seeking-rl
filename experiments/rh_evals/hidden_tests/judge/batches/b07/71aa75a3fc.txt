Essentially we need to count number of sequences (ordered) of length L (1..K) using alphabet of size 26 where each letter i can be used at most C[i] times in total string (over the whole L). Since the string length can vary up to K.

This is similar to counting permutations with repetitions limited. The total number of strings of length up to K respecting per-letter caps. This is a combinatorial counting problem; can use generating functions DP: DP over letters adding each letter's contribution using polynomial of having usage count for that letter, then multiply generating function to count sequences i.e., count of multisets permutations.

But order matters, not just multiset. For each multiset composition (counts x_i with sum = L, 0 ≤ x_i ≤ C[i]), number of distinct strings = multinomial L! / product x_i! . So total count = sum_{L=1..K} sum_{x_i, sum x_i = L, x_i ≤ C_i} L! / prod x_i! .

We can think sequentially adding letters: DP over letters processed so far and total length used, counting number of strings (ordered) formed using processed letters.

Let dp[l] = number of strings of length l using processed letters. Initially dp[0]=1 (empty string). When adding a new letter with availability up to c (max count), we need to update dp to incorporate adding k copies of this new letter placed among existing strings: this is similar to combinatorial convolution using binomial coefficients (positions insertion). Adding k identical letters of a new type into strings of length l produces new strings length l+k: number of ways to insert k identical letters into a string of length l is C(l + k, k) (choose positions for the new letters among l + k positions). And because letters are identical among themselves, that's consistent.

Thus we can iterate letters: for each letter with count limit c, we compute new dp2[new_len] = sum_{k=0..c} dp[old_len] * C(old_len + k, k) . This adds contributions of placing k copies of this letter into existing strings (keeping order of previous letters). This works because we are building strings by adding letters types one by one, and permutations counted correctly due to insertion of indistinguishable letters.

Finally answer = sum_{l=1..K} dp[l] after processing all letters (length up to K). Complexity O(26*K*max_c) naive O(K*totalC). totalC could be up to 1000 per letter and K up to 1000 leading O(26*K*maxC) ~ 26*1e6 26 million okay maybe borderline but okay in Python with optimization.
