[REASONING] We need to compute number of arrays length n over values 1..m with exactly k equal adjacent pairs. This is classic counting of runs. Equivalent to number of sequences with exactly k positions where arr[i]=arr[i-1]. Let's define transitions.

We can think of dynamic programming: For each position i (1-indexed), we consider number of equal pairs used so far and whether current element equal to previous or not. Another approach: Count arrays with exactly k equal adjacent pairs = choose positions of equal pairs among n-1, but values matter.

Let's DP: dp[i][j][eq] = number of arrays of length i, having j equal adjacent pairs up to position i, and eq indicates if arr[i] == arr[i-1] (i.e., last transition was equal). But we can reduce dimension using two states: same (arr[i]==arr[i-1]), diff (arr[i]!=arr[i-1]).

We need O(n*k) DP, n up to 1e5, k up to n-1, O(nk) too large. Need combinatorial formula.

Observation: The structure of equal pairs forms runs. Number of equal adjacent pairs = sum over runs (run length -1). If we have r runs (segments of equal numbers), then total equal pairs = n - r (since each run of length L contributes L-1 equal pairs, sum L = n, total equal pairs = n - number_of_runs). So exactly k equal pairs => number of runs r = n - k.

Thus we need count of arrays of length n over [1,m] with exactly r runs (segments of same value). This is classic: Count sequences of length n with exactly r runs where adjacent elements differ at run boundaries.

We can think of constructing sequence of runs: choose run lengths that sum to n with exactly r runs, each run length >=1. Number of ways to partition n into r positive integers = C(n-1, r-1). For each run, we need assign a value such that consecutive runs have different values (since run boundaries are where value changes). Number of ways to assign values: first run can be any of m values, each subsequent run must be different from previous run's value: (m-1) choices each. So total = C(n-1, r-1) * m * (m-1)^{r-1}.

Check: For r runs => r-1 changes (positions where arr[i]!=arr[i-1]): each change picks new value not equal previous: (m-1). That's consistent.

Thus answer = C(n-1, r-1) * m * (m-1)^{r-1} mod MOD, where r = n - k, and r must be >=1 and <= n (since runs count). Also r <= n and r >=1 obviously. If r < 1 or r > n => answer 0.

Edge cases: when m=1, (m-1)=0. Then only possible if r=1 (all same value) because there can be no changes. The formula also works: (m-1)^{r-1} = 0^{r-1}. If r-1>0 then zero. For m=1, only array all 1s, which has equal pairs = n-1 => k = n-1 => r = 1. Then C(n-1,0)=1, m=1, (m-1)^{0}=1 => answer 1. That's correct.
